# Lexicon Weaver

Интерактивный редактор глоссариев для онлайн-курсов с экспортом в SCORM. Преподаватель загружает структуру курса, размечает связи терминов с шагами курса, видит граф знаний и одной кнопкой собирает SCORM-пакет для LMS.

Проект состоит из двух взаимозаменяемо подключаемых частей:

- **`src/`** — React-фронтенд (Vite + TypeScript + D3.js).
- **`backend/`** — FastAPI-бэкенд (SQLAlchemy 2 + SQLite + FTS5 + BeautifulSoup4).

Фронтенд работает в двух режимах: на моках из `src/data/mock.ts` (по умолчанию) или с реальным API (`VITE_USE_API=1`). Переключение — одна переменная окружения, никаких изменений в коде.

## Возможности

- **Дашборд курсов.** Список курсов, глоссариев и статусов готовности; импорт курса по API-ключам или JSON-дампу; экспорт глоссария в SCORM 1.2/2004.
- **Редактор с тремя областями:**
  - левая панель — «Глоссарий» (поиск, фильтры по статусу, групировка по алфавиту, мульти-выделение и сбор данных) и «Добавление» (одиночный ввод или массовая вставка через разделитель);
  - центральный холст — двудольный граф на D3.js с force-симуляцией, drag, hover-подсветкой связных узлов, zoom/pan, drill-down `модули → уроки → термины` по двойному клику;
  - правая панель — «Контекст» (пусто / выбранный узел / выбранный термин) и «Фильтры» (вес связи, частота, логические функции, иерархический фильтр по модулям и урокам с tri-state чекбоксами, легенда).
- **Модальные окна:** добавить курс, создать глоссарий, настройки подключения, прогресс синхронизации, отчёт о синхронизации, настройки экспорта, подтверждение удаления, несохранённые изменения, окно вхождений термина в курс.
- **Drill-down графа.** Двойной клик по модулю показывает граф его уроков, двойной клик по уроку — терминологический «солнечный» граф этого урока с цветовой маркировкой статусов.
- **Live-связи.** Толщина рёбер пропорциональна весу связи, цвет — типу: чёрное ребро для первичного упоминания, серое для транзитного; стрелки указывают направление.
- **Хлебные крошки** и «домой» с гарантией: при наличии несохранённых изменений показывается модалка подтверждения.
- **Адаптивность.** На десктопе панели — фиксированные рельсы рядом с холстом. Ниже 900 px они превращаются в полноэкранные drawer'ы, выезжающие поверх холста, с тёмной подложкой и кликом «закрыть». На мобильном включён mutex: открытие одного drawer'а автоматически закрывает другой.
- **Сохранение позиций узлов.** После драга узла его позиция фиксируется и сохраняется в `localStorage` под ключом контекста (уровень + ID родителя). При следующем входе расположение узлов восстанавливается ровно там, где было оставлено.

## Технологический стек

| Слой | Решение |
| --- | --- |
| Сборка | Vite 7, TypeScript 5.9 |

## Запуск

Требования: **Node.js 20+ / npm 10+** и **Python 3.11+** (для бэкенда). Также понадобится Git и, опционально, Docker Desktop.

### 0. Клонирование репозитория

```bash
git clone https://github.com/d0ssh1/Glossary.git
cd Glossary
```

### Вариант 1: только фронт (моки, без бэкенда)

```bash
npm install
npm run dev
# → http://localhost:5173
```

`VITE_USE_API` не выставляется — приложение крутится на данных из `src/data/mock.ts`.

### Вариант 2: полный стек (фронт + бэк)

**Шаг A. Конфиг бэкенда.** Скопировать шаблон:

```bash
cd backend
cp .env.example .env        # Windows: copy .env.example .env
```

Значения по умолчанию подходят сразу. Для прямого импорта со Stepik (`source=stepik`) нужны OAuth-ключи — см. блок ниже.

**Stepik OAuth (опционально).** Регистрируем приложение на [stepik.org/oauth2/applications/](https://stepik.org/oauth2/applications/) (Authorization grant type = `Client credentials`), копируем Client ID и Secret в `backend/.env`:

```
LW_STEPIK_CLIENT_ID=ваш-client-id
LW_STEPIK_CLIENT_SECRET=ваш-client-secret
```

Без ключей доступен импорт из JSON-дампа (`source=mock` берёт `backend/mock_data/sample_course.json`), всё остальное (CRUD, FTS, SCORM) работает.

**Шаг B. Поднять бэкенд:**

```bash
# всё ещё в backend/
python -m venv .venv

# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt
python -m app.seed                       # засеять демо-данные (один раз)
uvicorn app.main:app --reload --port 8000
```

Бэкенд на `http://localhost:8000`. Swagger UI — `/docs`, ReDoc — `/redoc`. Тесты: `pytest -q`.

**Шаг C. Поднять фронт во втором терминале.** В корне проекта создать `.env.local`:

```
VITE_USE_API=1
VITE_API_URL=http://127.0.0.1:8000
```

Затем:

```bash
npm install
npm run dev
# → http://localhost:5173
```

Фронт подтянет курсы/глоссарии/термины из API. CRUD-операции в UI идут в SQLite-БД бэкенда. См. `backend/README.md` для полной таблицы эндпоинтов.

**Живая проверка импорта со Stepik (после настройки OAuth).** В UI нажать «Импорт курса» → выбрать Stepik. Или через curl:

```bash
# 1. Создать пустой курс
curl -X POST http://127.0.0.1:8000/courses/ \
  -H 'content-type: application/json' \
  -d '{"title":"Stepik 63054","url":"https://stepik.org/course/63054/promo"}'

# 2. Запустить фоновый импорт (вернёт 202 сразу)
curl -X POST http://127.0.0.1:8000/courses/2/import \
  -H 'content-type: application/json' \
  -d '{"source":"stepik","stepik_course_id":63054}'

# 3. Опросить статус (running → done)
curl http://127.0.0.1:8000/courses/2/import-status
```

Импорт выполняется в `BackgroundTasks`; для курса 63054 занимает ~30 с и кладёт в БД 4 секции / 22 урока / 206 шагов с очищенным `content_text` и FTS-индексом.

### Вариант 3: docker-compose

В корне есть `docker-compose.yml`. Запуск одной командой:

```bash
docker compose up --build
# фронт: http://localhost:5173
# бэк:   http://localhost:8000
```

Compose монтирует исходники и пересобирает при изменениях. SQLite-файл живёт в томе `lw-data`, чтобы пережить пересборку контейнера.

### Production-сборка фронта

```bash
npm run build      # артефакты в dist/
npm run preview    # локальный предпросмотр прод-сборки
npm run lint
```

## Как пользоваться

1. **Создать или открыть курс.** На дашборде нажмите «добавить» (модалка `Добавить курс`) и заполните название и URL. Дальше «Импорт курса» → введите ключи или подгрузите JSON-дамп — пойдёт симуляция прогресса с отчётом.
2. **Создать глоссарий.** В карточке курса — «глоссарии: добавить». Откройте глоссарий — попадёте в редактор.
3. **Добавить термины.** Вкладка «добавление» в левой панели: вводите по одному (Enter) или массово через разделители `, ; | . пробел`.
4. **Связать термины со шагами.** Выделите термины чекбоксами — внизу левой панели появится плавающая панель «выбрать всё / Собрать данные для глоссария». Связи можно править вручную в правой панели на вкладке «Контекст» через карандаш у блока «связи».
5. **Изучить граф.** Двойной клик по модулю → откроется граф его уроков, по уроку → терминологический граф этого урока. Толщина и цвет рёбер кодируют тип связи (см. «Легенду» во вкладке «Фильтры»).
6. **Экспорт SCORM.** На дашборде у глоссария — «перевести в scorm», выберите версию (1.2 / 2004) и идентификатор курса, нажмите «Скомпилировать и скачать».

## Замечания по реализации

- Глобальное состояние — единый `useReducer` без сторонней библиотеки: проект небольшой, действий ограниченное число, и `Action`-union даёт честную типизацию всех мутаций.
- Граф пересоздаётся при смене уровня/курса/выделения. D3 хранит позиции узлов внутри симуляции; drill-down заменяет всю модель.
- Несохранённые изменения отслеживаются флагом `hasUnsavedChanges`: переключение термина/узла при дёрти-состоянии открывает модалку и сохраняет отложенный диспатч в `pendingNavigation`, чтобы продолжить навигацию после ответа пользователя.
- Поиск в редакторе намеренно локальный — отдельно в левой и правой панели. Глобальный поиск на холсте был убран, так как локальные поиски уже покрывают сценарии.
- Все цвета статусов и линий — единственный источник правды в `lib/constants.ts`; и Tailwind-классы для DOM, и hex-значения для SVG.

## Интеграция с бэкендом

Бэкенд (FastAPI + SQLite + FTS5) живёт в `backend/`. Запуск:

```bash
cd backend
uvicorn app.main:app --reload --port 8000
```

Чтобы фронт обращался к API, скопируйте `.env.example` → `.env` и поставьте `VITE_USE_API=1`. По умолчанию `VITE_USE_API=0` — приложение использует моки из `src/data/mock.ts`, как и раньше.

Переменные:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `VITE_API_URL` | `http://localhost:8000` | Базовый URL FastAPI |
| `VITE_USE_API` | `0` | `1` — реальный backend, `0` — моки |

При `VITE_USE_API=1` `AppProvider` на старте подгружает курсы через `listCourses → getCourse → listGlossaries → getGlossary` и собирает фронтовое дерево через `lib/apiAdapter.ts`. Все доменные мутации (создание курса, глоссария, термина, удаление, массовая вставка) ходят через хук `useApi()` из `store/AppContext.tsx`. Хук оптимистично диспатчит локально, потом дублирует запрос в API.

## Тесты

**Фронт:**

```bash
npm run test         # Vitest, разовый прогон (16 тестов)
npm run test:watch   # watch-режим
npm run test:e2e     # Playwright, smoke-сценарии
npm run test:e2e:ui  # Playwright в интерактивном UI
```

Vitest покрывает `apiAdapter`, `graphData`, `nodePositions` и редьюсер `AppContext`. Playwright проверяет: дашборд открывается, модалка «Добавить курс» появляется, в редакторе рендерится `<svg>` графа.

**Бэк:**

```bash
cd backend
.venv\Scripts\activate         # или: source .venv/bin/activate
pytest -q                       # 5 тестов
```

`pytest` поднимает изолированную in-memory SQLite + FTS5 на каждый тест через `TestClient` FastAPI; проверяет health, CRUD курса/глоссария/термина, импорт JSON-дампа, FTS-collect и SCORM-экспорт.

## Дальнейшие улучшения

Базовая спецификация реализована полностью (см. историю коммитов). Что можно
доделать сверху для production:

- **Внешний кеш для Stepik OAuth-токена.** Сейчас токен живёт в памяти процесса
  uvicorn; для горизонтального масштабирования нужен Redis или аналогичное хранилище.
- **Playwright e2e против реального бэкенда.** Текущие e2e-тесты гоняются по моковой
  ветке. Чтобы тестировать против работающего API, добавьте в `playwright.config.ts`
  `webServer` с подъёмом `docker-compose up` или последовательным запуском
  uvicorn + vite, и переменную `VITE_USE_API=1`.
- **Прогресс-бар по секундам HTTP-fetch.** `import_steps_done/total` уже тикают на
  фазе персистенса. Бутылочное горлышко импорта Stepik — это HTTP-запросы к API
  до начала персистенса; чтобы показывать честный прогресс и в этой фазе, нужно
  декомпозировать `fetch_course_tree` на этапы и публиковать промежуточные счётчики.
- **Реальный drag-binding из LinkEditor.** Сейчас правка связей в правой панели
  сохраняется через `apiUpdateTerm`. Можно добавить полноценный diff и POST/DELETE
  по эндпоинтам `/bindings` для ручной правки без перевыполнения collect.
